All 32 Heuristics — EXTRACTION (why element was kept) vs PAIRING (why elements were paired)

IDCategoryTypeRuleThreshold
H01 Image EXTRACTION Skip images whose raw file size is below 5,000 bytes. Images this small are almost always 1×1 tracking pixels, tiny bullet icons, or corrupt embedded objects. Applied before reading pixel dimensions to avoid wasting time decoding useless data. filesize < 5,000 bytes
H02 Image EXTRACTION Skip images whose pixel area (width × height) is below 200,000 px². Institutional logos, government stamps, and risk meter icons are typically small. Real agricultural content such as field photos, charts, and observation maps are consistently larger. The threshold of 200,000 px² was chosen after visually inspecting 50 extracted images across 4 parser iterations. width × height < 200,000 px²
H03 Image EXTRACTION Skip images whose width to height ratio exceeds 8. BSV bulletins use thin horizontal bars as visual separators between sections, and some have wide institutional footer strips. These are extremely wide and short, giving ratios above 8. Real content images such as photos, charts, and maps are never this wide relative to their height. width / height > 8
H04 Image EXTRACTION Skip all images found on page 1 when the bulletin has more than 2 pages. Page 1 of a multi-page BSV bulletin is always a cover page containing the bulletin banner, the Écophyto logo, institutional headers, and decorative crop photos embedded in the title design. None of these are paired with article content. For 2-page bulletins the rule does not apply because page 1 contains real content. page = 1 AND total_pages > 2
H05 Image EXTRACTION Skip images whose internal PDF xref ID appears on more than 2 pages. In PDF internals a recurring image such as a page header logo is stored once and referenced by the same xref on every page it appears. By counting how many distinct pages reference each xref, we identify and discard these repeating decorative elements. Applied during parse_structure() at runtime; the xref counts are not stored in the output JSONL. xref_page_count > 2
H06 Section EXTRACTION A text span must be marked as bold to be considered a section header candidate. BSV section titles are always rendered in bold. Boldness is detected from the pymupdf font flag (bit 4) or by checking whether the string 'Bold' appears in the font family name. font flag bit 4 = True OR 'Bold' in font name
H07 Section EXTRACTION A bold span must have a font size at or above 85% of the effective maximum bold font size in the document. This dynamic threshold adapts to each bulletin's own typography instead of relying on a fixed point size. It ensures that body text rendered in bold (such as inline emphasis or table headers) is not mistaken for a section title. span size ≥ 0.85 × effective_max_bold_size
H08 Section EXTRACTION When computing the effective maximum bold font size, sizes that appear 2 times or fewer AND are more than 1.3 times larger than the next size down are excluded as decorative outliers. Some BSV bulletins have a single very large decorative title on the cover page that would otherwise inflate the threshold and suppress all real section headers. Excluding these rare outsized sizes keeps the threshold grounded in the document's recurring heading fonts. count ≤ 2 AND size > 1.3 × next_size → excluded
H09 Section EXTRACTION A bold span must begin at least 15 pixels from the left edge of the page. Some BSV bulletins have sidebar text running vertically along the left margin. This text is sometimes bold and large but is not a section title. The 15 pixel margin filters it out without affecting normally positioned headings. x0 ≥ 15 px
H10 Section EXTRACTION A section title candidate must be shorter than 80 characters. Genuine section headers such as 'MILDIOU', 'Situation actuelle', or 'Bilan météo' are always concise. Longer bold text is usually a sentence, a legal notice, or a block of emphasis text embedded in a paragraph. len(title) < 80 characters
H11 Section EXTRACTION A section title candidate must be at least 3 characters long. Single or double character bold spans appear in BSV layouts as decorative initials, bullet characters rendered in large bold font, or the first letter of page marker text such as 'P' from '<<>>'. These caused page markers to leak into section text before this filter was added. len(title) ≥ 3 characters
H12 Section EXTRACTION A section title candidate must not match any pattern in the is_bad_header() function. This function checks for known non-content patterns including single lowercase words, known sidebar institution names, pure number strings, and bulletin metadata strings. The list was built incrementally as specific false positives appeared during parser development. not in is_bad_header() pattern list
H13 Section EXTRACTION When two bold spans appear on the same page within 8 pixels of each other vertically, they are merged into a single section title. Some BSV section headers are split across two text spans in the PDF structure, for example 'Point' and 'météo/Phénologie' appearing as two consecutive bold blocks 3 pixels apart. Without merging, these would produce two separate sections instead of one. same page AND vertical gap ≤ 8 px → merge
H14 Table EXTRACTION Skip tables with fewer than 3 rows. pdfplumber detects tables by finding rectangular borders in the PDF. Very small grids of 1 or 2 rows are almost always decorative boxes, risk evaluation color legends, or layout artifacts rather than real observation data tables. row count < 3 → skip
H15 Table EXTRACTION Skip tables with fewer than 2 columns. A single-column table is almost never a real data table. It usually means pdfplumber found a bordered text box and misread its interior text as a single-cell table. column count < 2 → skip
H16 Table EXTRACTION Skip tables where the average non-empty cell text length exceeds 200 characters. When pdfplumber detects a bordered paragraph or a large risk description box as a table, all the text ends up in one or two very long cells. Real observation data tables have short cell values such as dates, numbers, percentages, and place names. avg non-empty cell length > 200 chars → skip
H17 Table EXTRACTION Skip tables where more than 50% of cells are empty or None. BSV bulletins use heavily merged cells for multi-row and multi-column headers. pdfplumber fills merged spans with the top-left cell value and leaves the rest as None. Tables where most cells are None are either fully empty layout grids or so fragmented by merging that their structure is unreadable. The 50% threshold keeps real sparse tables such as weekly weather forecasts while removing empty artifacts. empty cells / total cells > 50% → skip
H18 Text EXTRACTION When searching for a section title's position in the full PDF text string, the search starts from the position of the page marker <<>> where N is the page the header was detected on. Without this, the search could match the same title word earlier in the document, for example in a table of contents on the cover page, and then extract the wrong body text for that section. search from <<>> position, not from document start
H19 Text EXTRACTION Bullet prefix characters are stripped from a section title before searching for it in the full text string. Some BSV section headers begin with a bullet character (•, the Unicode private use character \uf0b7, or a plain hyphen) that is rendered as part of the title in the PDF but appears differently in the extracted text. Stripping these ensures the title match succeeds. strip •, \uf0b7, and leading hyphens before matching
H20 Text EXTRACTION For PDFs where no section structure was detected, the entire PDF text is returned as a single 'Document' fallback record. Without this fix, the page transition markers <<>>, <<>> etc. that we insert to track page boundaries appear verbatim in the text field of the output record. This rule strips them with a regex before writing the fallback text to the JSONL. re.sub(r'<<>>', '', full_text)
H21 Assign PAIRING Each extracted image is assigned to the section whose header appears closest above it on the same page, measured by vertical position in PDF coordinates. This reflects the standard BSV layout convention: a photo or chart always appears below the heading of the article it illustrates. The vertical distance between the image's top edge and each candidate header's top edge is computed; the smallest positive distance wins. argmin(header_top − image_top) where header_top < image_top, same page
H22 Assign PAIRING If no section header appears above an image on its page (the image is at the very top before any heading), the image is assigned to the first header on that page. This handles cases where a full-page illustration appears before the section title in the PDF's reading order, which occasionally happens in bulletin annexes. fallback: first header on the page
H23 Section EXTRACTION If the text body of a detected section is completely empty after splitting, that section's title is concatenated onto the title of the immediately following section. This handles PDFs where two consecutive bold lines together form one logical header but were detected as two separate candidates. Without this merge, one section would have a title but no content and the following section would have incomplete title information. if section text == '' → prepend title to next section
H24 Pair PAIRING Sections where the title is 'Document' are excluded from pair generation entirely. The 'Document' title is assigned as a fallback when our parser finds no bold headers in a PDF and cannot segment it into sections. In these cases the entire PDF becomes one undifferentiated block, and any image or table within it has no meaningful structural relationship to the text. section_title == 'Document' → skip all pairs from this section
H25 Pair PAIRING Sections whose text body is shorter than 50 characters are excluded from pair generation. Very short text such as 'Quelques pontes' (15 characters) or a single risk label like 'Le risque est élevé' cannot form a meaningful text pairing because there is not enough semantic content to describe an agricultural observation. The 50-character threshold was chosen to allow short but complete sentences while excluding stub fragments. len(text.strip()) < 50 → skip all pairs from this section
H26 Pair PAIRING A section must contain at least two distinct modalities (text, image, or table) to generate any pairs. A section with only text and no images or tables cannot produce a cross-modal pair. In the final clean run on 1,000 PDFs, 5,046 out of 6,992 sections were single-modality and were skipped by this rule. count({has_text, has_image, has_table}) ≥ 2
H27 Pair PAIRING For sections with both text and at least one image, one text+image pair is generated per image. If a section contains three images, three separate text+image pairs are generated, each sharing the same section text but pointing to a different image. This ensures every image in a section gets a paired text record. 1 pair per image in section
H28 Pair PAIRING For sections with both text and at least one table, one text+table pair is generated per table. If a section contains two tables, two separate text+table pairs are generated. Same logic as H27 but for tables. 1 pair per table in section
H29 Pair PAIRING For sections that contain both images and tables (regardless of whether text is present), pairs are generated for every combination of image and table in the section. A section with 2 images and 2 tables produces 4 image+table pairs. This cross-product approach ensures no image-table co-occurrence within a section is missed. 1 pair per (image, table) combination
H30 Meta EXTRACTION The bulletin date is extracted from the PDF filename by trying four regex patterns in order: 8-digit YYYYMMDD starting with '20', 8-digit DDMMYYYY where the last 4 digits form a valid year, YYYY-MM-DD or YYYY_MM_DD with separators, and DD-MM-YY or DD_MM_YY with 2-digit year. The ordered priority ensures that the most unambiguous format is tried first. Without ordered priority the patterns could conflict: a filename like '20190619' could be misread as DD=20, MM=19 (invalid month) if DDMMYYYY were tried first. YYYYMMDD → DDMMYYYY → YYYY-MM-DD → DD-MM-YY
H31 Meta EXTRACTION After a date is parsed by H30, it is validated before being stored. The day must be between 1 and 31, the month between 1 and 12, and the year between 2000 and 2030. This catches malformed filenames that accidentally match a date pattern but produce impossible values such as month 20 or year 1409. 1 ≤ day ≤ 31 AND 1 ≤ month ≤ 12 AND 2000 ≤ year ≤ 2030
H32 Meta EXTRACTION The crop category is detected by scanning the PDF filename for keyword substrings from a predefined dictionary called CROP_CATEGORIES. BSV filenames systematically encode the crop type as a keyword such as 'viti', 'maraichage', 'grandes_cultures', 'arbo', 'lin', 'colza', and so on. The dictionary maps each keyword to a human-readable category name. Note: per supervisor feedback, this metadata will be replaced in a future version by a SPARQL query to the PHB Knowledge Graph where it is already stored. keyword match in filename against CROP_CATEGORIES dict
H33 Section EXTRACTION Text color brightness above 200 forces level 1 classification. Main section headers in BSV bulletins are often rendered as white or light-colored text on a colored background box. Brightness is computed as 0.299×R + 0.587×G + 0.114×B from the RGB color value. brightness(color) > 200 → level 1
H34 Section EXTRACTION Skip bold spans whose text ends with punctuation marks. Genuine section headers never end with a period, comma, semicolon, exclamation mark, or question mark. This filter removes bold emphasis text embedded in body paragraphs such as 'Note importante.' or 'Attention,'. last char not in . ! ? , ;
H35 Section EXTRACTION Skip bold spans whose text is entirely lowercase. Section titles always contain at least one uppercase letter. Fully lowercase bold spans are almost always hyperlink fragments split across PDF text spans, such as 'mildiou' or 'black rot' appearing inside 'Consultez la fiche «mildiou»'. text != text.lower()
H36 Image EXTRACTION Skip images where more than 80% of pixels are near-white (R>240, G>240, B>240). Institutional header banners, blank letterhead pages, and footer contact blocks have large white backgrounds that real agricultural content images do not. near_white / total > 0.80
H37 Image EXTRACTION Skip images where a single quantized color dominates more than 70% of pixels. Solid-color decorative blocks (orange contact pages, colored banners) fail this check while photographs with natural color variation always pass. max(color_counts.values()) / total > 0.70
